Files created: `scripts/3d/main_3d.gd`, `scripts/3d/main_3d_placeholders.gd`, `scripts/3d/tests/main3d_smoke.gd` (plus their `.gd.uid` sidecars), `scenes/3d/stubs/stub_enemy_3d.tscn`, `scenes/3d/tests/main3d_stub_arena.tscn`, this file. No shared file was edited.

## Deviations and decisions

| # | Area | Deviation | Why | Action for the lead / WP8 |
| --- | --- | --- | --- | --- |
| 1 | Verification (section 11, 12) | `--check-only --script res://scripts/3d/main_3d.gd` fails with `Compile Error: Identifier not found: StoryBook`. `--check-only` never instantiates autoloads, so the compiler cannot resolve `CombatFx`, `LootMenu`, `InventoryScreen`, `StoryBook`. The untouched 2D `scripts/main.gd` fails the same way at its line 147. `main3d_smoke.gd` fails only because it depends on `main_3d.gd`. | Godot 4.7.2 behaviour, not a script fault. | Treat the headless scene run (`main3d_stub_arena.tscn --quit-after 240`, exit 0, no `SCRIPT ERROR`) as the compile proof for autoload-referencing scripts. `main_3d_placeholders.gd` passes `--check-only`. Consider adding this note to section 11. |
| 2 | Test scene placement | The stub enemy is 5.0 m from the spawn (4 cells in x, 3 in z), which is a Manhattan distance of 7 cells, one more than `COMBAT_TRIGGER_DISTANCE_CELLS`. Combat therefore starts when the smoke test's first exploration move closes the gap (about 40 frames in), not on frame 1. | The requested sequence needs an observable exploration phase before combat; at Manhattan 6 or less combat starts on the first `_process`. | None. Both readings of "about 5 m" hold; combat starts well inside the first 120 frames. |
| 3 | Constants in metres | Pixel constants of `main.gd` became metres: `TURN_MODE_ENEMY_BLOCKER_EXTRA_RADIUS` 20 px to 0.6 m; enemy personal-space padding 6 px to `ENEMY_PERSONAL_SPACE_PADDING_M` 0.2 m; `TEST_LOOT_SPREAD` 26 px to `TEST_LOOT_SPREAD_M` 0.8 m; the enemy approach stop `max(4 px, attack_range - 20 px)` to `max(ENEMY_APPROACH_MIN_M 0.2, attack_range - ENEMY_APPROACH_BUFFER_M 0.4)`, mirroring the 3D player's `attack_approach_buffer` 0.4 m. `ENEMY_CLICK_RADIUS` (24 px) is gone: the click ray hits the body. | About 32 px to the metre on the 2D tilesets; the contract fixes only `TURN_MOVE_METERS`, `ENGAGE_RADIUS_METERS`, `COMBAT_TRIGGER_DISTANCE_CELLS`. | Add the metre values to section 2 if accepted. |
| 4 | Player placement (section 9) | `_place_player` uses a `Spawn_default` node when the level has one (the `LevelLoader` naming), else the 2D rule (map centre cell + `PLAYER_SPAWN_OFFSET`, clamped to the grid from the Ground box). | Lets a level author choose the start without a tilemap; the 2D rule stays as the fallback. | `LevelLoader.apply_spawn` casts the spawn `as Node2D` and the player `as Node2D`; WP8's additive edit to `level_loader.gd` must widen both to `Node3D`, or 3D `Spawn_<name>` nodes are ignored with a warning. |
| 5 | Dropped 2D-only helpers | Not ported (no 3D equivalent): tile set creation and tile picking (`_setup_tile_set`, `_add_single_tile_source`, `_pick_ground_tile`, `_should_place_tree`, `_is_path_cell`, `_cell_noise`, ...), `_load_custom_layout_mode`, `_center_camera_on_layer`, `_carve_enemy_holes_in_navmesh`, `_restore_navmesh`, `_world_to_cell(layer, ...)`, `_refresh_turn_meter_world_units`, exports `prefer_hand_painted_layout` and `runtime_canvas_modulate_color`. `_cache_custom_blocked_cells` became `_cache_blocked_cells_from_props` (cells under layer 4 boxes in the navigation region). | Tilemaps, `CanvasModulate` and `NavigationPolygon` do not exist in 3D. The AStarGrid2D helpers were kept on `GroundMath` cells. | None. |
| 6 | Popups (section 7) | Without WP5, `_fx_popup` unprojects the world point through the active camera at spawn time and hands `CombatFx.popup_text` a screen-space `Vector2`; such a popup does not follow camera motion. Popups anchor to the actor's `OverheadAnchor` (fallback `POPUP_HEIGHT_M` 1.8 m) instead of the 2D `Vector2(0, -50)` px offset. With WP5 present (`CombatFx.has_method("set_world_projector")`) the world `Vector3` is passed through unchanged. | `CombatFx.popup_text` is typed `Vector2` until WP5 widens it. | Remove the fallback branch after WP5 (`TODO(3d-integration)`). |
| 7 | Camera shake | `CombatFx.shake` finds no `Camera2D` in 3D and does nothing. When WP5 adds `set_shake_target`, `main_3d.gd` registers `_apply_camera_shake_offset`, which converts the pixel offset to metres (`camera.size / viewport height`) and writes `CameraRig.shake_offset` or the fallback camera's `h_offset` / `v_offset`. | Section 7 names the adapter but not who wires it. | Confirm WP5's offset unit; adjust the conversion if the adapter already delivers metres. |
| 8 | Loot guards (section 8) | `LootMenu.request_loot` and `LootDropper.drop_items` are typed `Node2D` until WP6. A `has_method` check cannot tell `Node2D` from `Node`, so the coordinator reads the first parameter's class from `get_method_list()` (`_method_arg_accepts_node3d`) and calls through `call()` only when a `Node3D` is accepted. Until then the test loot is skipped with a printed note and a pickup click falls through. Out-of-reach loot: the coordinator itself walks the player to the pickup (turn move in combat); the 2D level moved to the raw click position. | Static typing would otherwise fail on the 2D signatures. | Works unchanged once WP6 lands; the guards can then be removed. |
| 9 | Overlays (section 7) | Placeholder inner classes are `RangeRingStub`, `PathPreviewStub`, `CounterPromptStub`, `OverheadBarsStub` (an inner class named `RangeRing` or `CounterPrompt` hides the 2D global class and is a parse error). The path preview's distance label is drawn by the overlay node (`show_path(points, used_m, remaining_m)`), not by the coordinator, and turns red when `used_m` equals the remaining budget, as the 2D line did when over budget. | Section 7's API has no colour or label parameters. | Delete `main_3d_placeholders.gd` and repoint `_create_overlay` when WP5 lands. |
| 10 | Counter prompt hookup | New public helper `main_3d.acquire_counter_prompt(owner: Node3D) -> Node3D`: creates a prompt through the overlay factory and parents it under the owner's `OverheadAnchor`. The coordinator itself never drives the prompt (the enemy does, as in 2D). | Gives WP3c one call that does not care whether the placeholder or WP5's node is present. | Optional for WP3c; the enemy may also instantiate `CounterPrompt3D` itself. |
| 11 | Navmesh | If `NavigationRegion3D.navigation_mesh` has no polygons and `bake_navmesh_if_empty` is on, `_ready` bakes it (threaded) and `is_navmesh_ready()` turns true two physics frames after `bake_finished`. Paths use the actor's `NavigationAgent3D` map when set, else `get_world_3d().navigation_map`. | The test scene cannot ship an editor-baked mesh. | WP7 arenas ship a baked mesh, which skips the bake. |
| 12 | Input | An exploration click on an enemy now marks the input handled (2D left it unhandled after `set_attack_target`). A click that hits nothing (sky) is left unhandled. Hover uses a physics ray per frame from `_process`, like the 2D per-frame mouse test. | Ray picking has no "empty" world position to fall back to. | None. |
| 13 | Position blocking | `_is_player_position_blocked` queries layers 4 (props) and 2 (actors) and excludes the player by RID. The 2D version used mask `1 | 4` (2D layer semantics) and passed the node object where an RID array is expected; that path is unused in both versions. | 3D layer table, section 3. | None. |
| 14 | Enemy spawning | `_spawn_additional_enemy(target_cell, search_radius)` with `@export var enemy_scene` (default `scenes/3d/stubs/stub_enemy_3d.tscn`). The 2D `main.gd` at `afeee19` no longer has a spawn helper although `CODEBASE_GUIDE.md` still describes one; this is a new helper written to the guide's description. | Task requirement. | WP8: set `enemy_scene` to `scenes/3d/enemy_3d.tscn`; the guide's spawning paragraph is stale for 2D. |
| 15 | Smoke test | `main3d_smoke.gd` sets `Engine.max_fps = 60` when the display server is headless. Headless otherwise paces at about 145 fps, which makes 240 frames under two seconds of game time, too short for the 0.6 s + 0.3 s enemy-turn beats plus movement. | Test pacing only; the coordinator's constants are unchanged. | None. |
| 16 | Camera fallback | A node named `CameraRig` that lacks `set_follow_target` is ignored and the plain `Camera3D` is used (created at runtime if the level has none). | Keeps the scene runnable with a half-wired rig. | WP8 adds the WP2 `CameraRig`; the code prefers it automatically. |

## WP8 wiring list (`TODO(3d-integration)` markers in `scripts/3d/main_3d.gd`)

- `_pick_ground`, `_pick_enemy`, `_pick_pickup`: replace with `WorldPicker` (WP2).
- `_setup_camera` / `_update_camera`: drop the fallback camera once every 3D level has the WP2 `CameraRig`; the rig path (`set_follow_target`, `set_zoom_size`, `focus_between`, `clear_focus`, `get_camera`) is already wired.
- `_setup_combat_fx_adapters` and `_fx_popup`: auto-wire when WP5 adds `set_world_projector` / `set_shake_target`; delete the projection fallback afterwards.
- `_create_overlay`: return the WP5 nodes; delete `main_3d_placeholders.gd`.
- `_spawn_test_loot`, `_try_click_pickup`: work unchanged once WP6 widens `LootDropper.drop_items` and `LootMenu.request_loot`; remove the guards then.
- `enemy_scene` default: `scenes/3d/enemy_3d.tscn` (WP3c).
- `LevelLoader.apply_spawn`: widen `as Node2D` to `Node3D` (additive edit allowed for WP8) so `Spawn_<name>` works in 3D.
